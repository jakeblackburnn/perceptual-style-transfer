**Five findings that determine which experiments would be interpretable**

1. **The loss already accepts another generator's output, but its experimental controls are unreliable.** `perceptual_loss` takes generated, content, and style tensors; it does not call a generator (`style_transfer/loss.py:11`). It nevertheless obtains a process-global VGG that requires prior initialization (`style_transfer/loss.py:24`, `style_transfer/feature_extractors/vgg.py:44`, `style_transfer/feature_extractors/vgg.py:58`). More seriously, it reads `style_layer_weights` and never multiplies by them in either branch (`style_transfer/loss.py:29`, `style_transfer/loss.py:40`, `style_transfer/loss.py:49`, `style_transfer/loss.py:57`). The standard and standard-weighted presets therefore specify different weights but implement the same objective with this code (`style_transfer/config/layer_presets.py:6`, `style_transfer/config/layer_presets.py:14`). A difference between their old checkpoints cannot establish that layer weighting helped; their training-code provenance is not recorded. Recommendation: repair and verify this control before any new weight sweep, preserving a named legacy objective for comparison.

2. **The activation visualizer currently observes a different input distribution from training.** Its transform applies ImageNet normalization, then `VGG.forward` applies it again (`style_transfer/utils/visualize.py:312`, `style_transfer/feature_extractors/vgg.py:23`). Its cache key contains an image name, without a preprocessing or extractor fingerprint (`style_transfer/utils/visualize.py:327`), and its display independently rescales each channel to its own minimum/maximum (`style_transfer/utils/visualize.py:139`). The hooks capture detached outputs from every VGG module (`style_transfer/utils/activation_extractor.py:7`). Recommendation: retain the useful local viewer, correct normalization, invalidate incompatible caches, and add actual activation/gradient magnitudes; equally bright heatmaps do not demonstrate equally useful loss layers. The viewer already binds to localhost (`style_transfer/utils/visualize.py:272`).

3. **Multi-image style input already exists, but it is an average target rather than a selectable vocabulary.** The trainer accepts a style directory (`style_transfer/train.py:123`), and the loss averages squared Gram distances across every generated/style pair (`style_transfer/loss.py:51`). Algebraically, `mean_s ||G - G_s||² = ||G - mean_s G_s||² + constant`: the gradient attracts each output toward the set's mean Gram matrix. Sampling one style at a time changes gradient variance, not this expected objective. The generator receives only the content tensor (`style_transfer/train.py:35`, `style_transfer/models.py:90`). Recommendation: test whether a coherent set improves a particular style; introduce explicit conditioning only when the objective is to choose or interpolate styles. Do not describe a heterogeneous directory as an arbitrary-style model.

4. **Architecture and resolution comparisons currently mix several effects.** Small/medium/big jointly choose width, residual depth, and endpoint kernel sizes (`style_transfer/models.py:9`). Affine instance normalization and nearest-neighbor resize followed by convolution already exist (`style_transfer/models.py:47`, `style_transfer/models.py:69`, `style_transfer/architectures/residual_block.py:7`); replacing transposed convolution is not a new experiment here. The two stride-two reductions followed by two doublings produce `4*ceil(H/4)` by `4*ceil(W/4)` outputs (`style_transfer/models.py:53`, `style_transfer/models.py:58`, `style_transfer/models.py:71`, `style_transfer/models.py:77`). A read-only forward inspection confirmed `65×97 -> 68×100`; the current shape test uses only `64×64` (`tests/test_models.py:6`). Training squashes images to squares, while inference preserves input dimensions before the model (`style_transfer/dataset.py:61`, `style_transfer/inference.py:17`). Recommendation: establish exact output dimensions and isolate architecture variables before interpreting scale robustness.

5. **Recorded training loss is insufficient to rank models or reproduce a run.** Feed-forward logs contain only stage, epoch, aggregate loss, and time (`style_transfer/utils/metrics.py:66`); metadata contains stages and limited dataset information (`style_transfer/utils/metrics.py:42`, `style_transfer/dataset.py:50`). Dataset subsets use unseeded `random.sample`, including when fraction is one (`style_transfer/dataset.py:29`). Final feed-forward and diffusion saves contain weights alone (`style_transfer/train.py:173`, `diffuser/train.py:137`). Recommendation: add fixed validation manifests, separate loss components, and resolved checkpoint metadata before interpreting the existing collection as a controlled ablation. The actual constructor always loads VGG19, while the legacy preset conversion discards `feature_extractor` (`style_transfer/feature_extractors/vgg.py:18`, `style_transfer/config/layer_presets.py:100`); a config label alone cannot select another backbone.

**The key unresolved mechanism, derived from the current code:** training noises the original content `c` and gives that same clean content to the denoiser (`diffuser/train.py:40`, `diffuser/train.py:46`, `diffuser/models.py:39`). For `x_t = sqrt(a)*c + sqrt(1-a)*epsilon`, the exact conditional answer is `epsilon = (x_t - sqrt(a)*c)/sqrt(1-a)`. Thus perfect epsilon prediction reconstructs the original content; stylistic departure requires accepting a different optimum. This is a deliberate competing-objective problem, not merely insufficient U-Net capacity. A cutoff may improve conditioning, but cannot remove this conflict. Before clipping, the magnitude of `d x0 / d epsilon` grows as `sqrt((1-a)/a)`; clipping then zeros gradients outside the allowed interval (`diffuser/schedule.py:54`). Measure gradient balance and clipping saturation rather than attributing everything to high-noise timesteps.

**Theme A — measurement and loss design**

**E1. Establish a benchmark that can reject misleading improvements.**

- **Hypothesis:** a fixed multi-criterion benchmark will distinguish useful stylization from low training loss, identity copying, and noisy texture.
- **Smallest answer:** evaluate three existing checkpoints on 24 fixed photographs, plus identity, blur, and tiled-style negative controls; score separate content/style distances and obtain 24 blinded pair preferences. Audit the activation viewer on the same images against the training extractor. Old checkpoints are candidates, not controlled training comparisons.
- **Needed:** an evaluation-only CLI, image manifests, named loss components, optional DISTS/LPIPS evaluators, and corrected/fingerprinted activation extraction (findings 2 and 5). One CSV plus an image grid replaces ad hoc visual comparisons; no tracking service.
- **Cost:** zero training; roughly 0.25–1 MPS inference hour and 1–2 owner hours for calibration.
- **Support / stop:** retain metrics that catch the negative controls and agree with at least 75% of the small preference set; reject a combined quality score if it rewards identity or noise. This is a calibration gate, not validation of a universal metric.
- **Read:** Zhang et al., [The Unreasonable Effectiveness of Deep Features as a Perceptual Metric](https://arxiv.org/abs/1801.03924) (LPIPS, 2018); Ding et al., [Image Quality Assessment: Unifying Structure and Texture Similarity](https://arxiv.org/abs/2004.07728) (DISTS, 2020/2021). Neither establishes a complete artistic-style judge.

**E2. Make layer weighting a real experiment.**

- **Hypothesis:** correctly applied shallow-heavy versus deep-heavy VGG weights change texture scale at a comparable content-preservation level.
- **Smallest answer:** uniform, shallow-heavy, and deep-heavy weights on exactly the same layer set; normalize each vector to the same sum, then train a small generator for 1,000 updates per arm/style/seed at 256px. Compare raw per-layer losses and image-gradient norms before training, since equal weight sums do not equalize gradients.
- **Needed:** apply the ignored weights, expose content weight in resolved training config, report raw and weighted terms, and verify that changing one coefficient changes its gradient. Cache fixed style statistics using an explicit cache key; preserve a legacy-loss option (finding 1).
- **Cost:** about 2–6 MPS training hours, or 0.5–2 GPU hours.
- **Support / stop:** retain a weighting that improves the E1 tradeoff consistently or predictably changes brush scale; stop sweeping weights if differences vanish across seeds after calibration. A lower differently weighted training total is not evidence.
- **Read:** Johnson, Alahi, and Fei-Fei, [Perceptual Losses for Real-Time Style Transfer and Super-Resolution](https://arxiv.org/abs/1603.08155) (2016).

**E3. Test a cheaper feature extractor before a larger one.**

- **Hypothesis:** a frozen MobileNetV2 feature loss can preserve acceptable style/content quality at materially lower training cost than VGG19.
- **Smallest answer:** select three spatial feature stages at comparable strides, use the same Gram statistic, and calibrate loss/gradient scales on a fixed batch; compare VGG19 and MobileNetV2 for 1,000 updates per style/seed. Report both equal-update quality and quality per wall-clock hour.
- **Needed:** a small explicit extractor constructor and feature-name map, with extractor-owned normalization and weight identifiers; remove the VGG singleton and misleading ignored extractor field (findings 1 and 5). Stop VGG evaluation after the last requested layer: the current forward loop traverses every module (`style_transfer/feature_extractors/vgg.py:32`).
- **Cost:** about 1–4 MPS training hours, or 0.5–1.5 GPU hours.
- **Support / stop:** promote if measured training throughput improves at least 1.5× while meeting E1's quality tolerance; stop if only VGG's numerical loss decreases or the alternate backbone loses the defining textures. This tests one lightweight alternative, not all non-VGG representations.
- **Read:** Sandler et al., [MobileNetV2: Inverted Residuals and Linear Bottlenecks](https://arxiv.org/abs/1801.04381) (2018); Zhang et al.'s LPIPS paper above for why representations merit comparison, not a guarantee MobileNet will work here.

**E4. Ask which style statistics are actually necessary.**

- **Hypothesis:** channel means and standard deviations retain enough style information for some references while reducing the cost and overconstraint of full Gram matching.
- **Smallest answer:** VGG Gram versus mean/std matching, holding extractor, selected layers, generator, and content loss fixed; calibrate scales first, then run 1,000 updates per style/seed. Treat centered covariance as a later third arm only if this comparison exposes a useful difference.
- **Needed:** an explicit `style_statistic` choice with defined reductions and per-layer measurements. Replace the raw-feature Boolean: its existing branch compares aligned spatial positions, which imposes layout correspondence and requires compatible feature-map sizes (`style_transfer/loss.py:42`).
- **Cost:** about 1–4 MPS training hours, or 0.5–1.5 GPU hours.
- **Support / stop:** retain mean/std if it meets quality tolerance and lowers measured loss-evaluation time or improves color/structure; reject it for styles whose cross-channel textures disappear. Lower mean/std distance by itself cannot win its own comparison.
- **Read:** Li et al., [Demystifying Neural Style Transfer](https://arxiv.org/abs/1701.01036) (2017), connecting Gram matching to distribution matching; Huang and Belongie's AdaIN paper linked in E8.

**Theme B — generators, resolution, and style collections**

**E5. Find which generator components earn their cost.**

- **Hypothesis:** independent changes to depth, width, normalization, and interpolation reveal a smaller or cleaner generator without sacrificing the reference styles.
- **Smallest answer:** a 32-channel, five-block, 9px-endpoint baseline plus four one-factor changes: width 16, depth two, GroupNorm with eight groups, or bilinear upsampling. Hold endpoint kernels fixed. Screen at 1,000 updates per arm/style/seed; combine winners only in a later run.
- **Needed:** explicit numeric width/depth and normalization/upsampling fields instead of relying on the coupled size presets (finding 4). Keep one generator implementation, not five forks.
- **Cost:** about 3–10 MPS training hours, or 1–3 GPU hours.
- **Support / stop:** retain a variant with at least 25% lower measured latency/memory at quality tolerance, or a consistent reduction in edge/grid artifacts. Reject changes that only reduce parameter count. InstanceNorm remains the reference; no presumption GroupNorm is better.
- **Read:** Ulyanov et al., [Instance Normalization: The Missing Ingredient for Fast Stylization](https://arxiv.org/abs/1607.08022) (2016); Odena et al., [Deconvolution and Checkerboard Artifacts](https://distill.pub/2016/deconv-checkerboard/) (2016, technical essay) for interpreting resampling artifacts.

**E6. Preserve style across aspect ratios and output scales.**

- **Hypothesis:** aspect-preserving crops plus mixed training scales improve large and panoramic outputs compared with square-resize-only training.
- **Smallest answer:** first measure existing models at 256/512/1024px and odd portrait/panorama sizes; then compare square resizing against aspect-preserving random crops, and against those same crops at mixed 128/256/384px, for 1,000 updates per arm/style/seed. Keep style-reference scaling explicit. Report equal-update and equal-pixel-budget results.
- **Needed:** training transform config, seeded crop/scale sampling, exact padding/unpadding at inference, and a consistency score between low-resolution output and downsampled high-resolution output (finding 4). Default to whole-frame inference initially.
- **Cost:** zero training for the audit; roughly 2–8 MPS training hours or 0.5–2 GPU hours for the three-arm pilot.
- **Support / stop:** require exact original dimensions, at least 20% lower cross-scale inconsistency, and acceptable fine texture. Stop if “consistency” is achieved by blur or the mixed-scale model simply changes brush size unpredictably.
- **Read:** Johnson et al.'s perceptual-loss paper in E2 as the feed-forward baseline; the scale-consistency measurement here is a proposed extension.

**E7. Compare one painting with a coherent style set.**

- **Hypothesis:** a small coherent reference set improves transfer to varied content, while a mixed set washes out recognizable style.
- **Smallest answer:** one anchor image, eight curated references sharing its palette/mark-making, and an eight-image heterogeneous control; use the same generator, 512 content images, and 1,000 updates per arm/seed. Evaluate on held-out content and held-out related reference crops, including per-reference variance rather than only average distance.
- **Needed:** a manifest with explicit style-set membership and sampling weights, and cached mean Gram targets (finding 3). Preserve the style-set variance constant if comparing absolute logged losses; dropping it preserves gradients but changes the reported number. No new conditioning architecture is needed for this question.
- **Cost:** about 1–3 MPS training hours, or 0.25–1 GPU hour.
- **Support / stop:** promote a coherent set if its outputs beat the single anchor on diverse content without losing characteristic marks; stop broad-directory training if results converge toward generic colors/textures. The heterogeneous control tests this failure explicitly.
- **Read:** Li et al., [Demystifying Neural Style Transfer](https://arxiv.org/abs/1701.01036) (2017). The mean-target interpretation follows directly from this repo's squared pairwise loss, not from an observed multi-style success.

**E8. One selectable model: conditional normalization before arbitrary-style training.**

- **Hypothesis:** shared convolutions with style-specific instance-normalization affine parameters can match three specialist models closely enough while enabling style interpolation.
- **Smallest answer:** Kanagawa, Starry Night, and Collioure; train three specialists and one conditional model with balanced style IDs and equal content exposures per style, for two seeds. Evaluate endpoints and five interpolation points. As a separate no-training reference, evaluate an authors' pretrained AdaIN model on these three and three unseen styles; keep its different training data visible.
- **Needed:** style-indexed normalization parameters, stable style IDs in checkpoints, and style-to-output target association. The current all-pairs loss must not score every conditioned output against every different style (`style_transfer/loss.py:53`). This replaces duplicated specialist weights if successful; it does not require an embedding service or registry.
- **Cost:** about 3–10 MPS training hours, or 1–3 GPU hours, plus less than one inference hour for the AdaIN reference; implementing conditioning adds several focused engineering hours.
- **Support / stop:** promote if all three endpoints stay within quality tolerance, model storage is substantially below three specialists, and interpolation is controllable. Stop if one style dominates or endpoints degrade. Conditional normalization covers trained styles; unseen-style support would require the separate AdaIN/encoder route, not just another ID.
- **Read:** Dumoulin et al., [A Learned Representation for Artistic Style](https://arxiv.org/abs/1610.07629) (2017); Huang and Belongie, [Arbitrary Style Transfer in Real-time with Adaptive Instance Normalization](https://arxiv.org/abs/1703.06868) (2017).

**Theme C — moving images and practical speed**

**E9. Suppress flicker without smearing motion.**

- **Hypothesis:** a small temporal-consistency term reduces frame-to-frame texture flicker while preserving the still-image style.
- **Smallest answer:** establish framewise baselines on three 5–10-second clips (static scene, camera pan, moving/occluding subject); fine-tune one style for 500 updates on separate short clips, comparing zero versus nonzero temporal weight for two seeds. Include a simple output-smoothing baseline so a learned method must beat a cheap alternative.
- **Needed:** paired-frame loading, fixed optical flow, occlusion masks, a warp-consistency loss, and aligned-frame evaluation. Use motion from the original frames. These add an optional video experiment around the image generator; current inference processes one image tensor at a time (`style_transfer/inference.py:36`).
- **Cost:** about 1–4 MPS training hours plus 0.5–2 hours for flow/rendering, or 0.5–1.5 GPU hours total.
- **Support / stop:** target at least 30% lower occlusion-masked warp error while staying within still-image quality tolerance; reject ghosting, frozen texture, or blur that merely lowers the metric. Judge a held-out motion clip, not adjacent training frames.
- **Read:** Ruder, Dosovitskiy, and Brox, [Artistic Style Transfer for Videos](https://arxiv.org/abs/1604.08610) (2016).

**E10. Measure the simplest fast local inference path.**

- **Hypothesis:** an existing small model can run faster or with a simpler runtime through ONNX and reduced precision without a visible loss of quality.
- **Smallest answer:** one checkpoint at three sizes, including odd dimensions; compare PyTorch FP32 against ONNX FP32 first, then FP16 where supported and static INT8 only on a supported backend. Time warm runs, startup, and end-to-end image conversion separately. Only after numerical parity, try a single localhost page with ONNX Runtime Web; compare it to the local Python path, not a remote service.
- **Needed:** executable export parity checks and benchmark harness. An opset-11 dynamic-axis exporter already exists, but its check verifies model structure rather than output equality (`style_transfer/utils/convert_to_onnx.py:47`, `style_transfer/utils/convert_to_onnx.py:62`). A browser pilot would replace the inference process for that optional path; the current demo calls Python inference (`R/demo/core/inference.py:10`, `R/demo/core/inference.py:80`).
- **Cost:** zero training; approximately 0.5–2 device-hours for calibration/benchmarks and 4–8 implementation hours. Quantization-aware retraining is a later decision.
- **Support / stop:** require export FP32 parity (initial target maximum absolute error below `1e-4`) and either 1.5× end-to-end speedup or a clear installation benefit. For reduced precision, check artifacts and E1 quality, not FP32 tolerance. Stop if normalization/operator fallbacks erase the advantage; INT8 is not assumed faster on Apple GPUs.
- **Read:** Jacob et al., [Quantization and Training of Neural Networks for Efficient Integer-Arithmetic-Only Inference](https://arxiv.org/abs/1712.05877) (2018); official [ONNX Runtime Web documentation](https://onnxruntime.ai/docs/tutorials/web/) and [quantization guidance](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html). Actual browser/device/operator support needs verification in the pilot.

**Theme D — diffusion as a falsifiable research line**

**E11. Separate a useful perceptual signal from conflicting denoising targets.**

- **Hypothesis:** restricting perceptual supervision to low-noise predictions produces a better style/content tradeoff than all-timestep supervision without destroying the denoising baseline.
- **Smallest answer:** use the current small U-Net at 64px, 32 flower training images, eight validation images, four untouched test images, one style, 1,000 updates, and two seeds. Compare A: epsilon MSE only; B: MSE plus perceptual loss at all timesteps; C: the same auxiliary coefficient with cutoff 0.2. Use identical initializations, batch/noise sequences, and evaluation sampling seeds. Hold scheduler, EMA, architecture, and clipping fixed. Use stratified timestep groups with one of every five examples below cutoff, and a documented reduction that matches expected auxiliary weight across B/C.
- **Needed:** a step cap, full configuration/seed manifests, per-example content/style terms, fixed-noise validation by timestep band, eligible-example counts, pre-clamp saturation, and separate objective gradient norms/cosines. Existing masked scoring averages only eligible samples; with independent timesteps and batch two, 64% of batches have none, by `(1-0.2)^2` (`diffuser/loss.py:30`, `diffuser/config/experiments.py:16`). Logging total loss cannot resolve that variation.
- **Cost:** about 2–6 MPS training/evaluation hours, or 0.5–2 GPU hours. The existing four-image, one-epoch result is too short to budget a convergence run from.
- **Support / stop:** first require A to beat a zero-epsilon predictor on fixed-noise validation and reconstruct content better than its untrained counterpart. Otherwise debug the denoiser before drawing conclusions about perceptual loss. Support C if it lowers held-out style distance by at least 20% relative to A, preserves content within 5%, keeps validation MSE within 10%, and improves the tradeoff over B in both seeds. If style gains require severe denoising degradation, stop this auxiliary-training recipe.
- **Diagnostic follow-up only if needed:** noise feed-forward stylized targets while still conditioning on original content; compare zero/nonzero auxiliary weight at the same budget. If this paired-target control learns while the content-target formulation fails, that supports the target-conflict explanation. It is a teacher-distillation control, not evidence that diffusion improved on its teacher. Budget another 1–3 MPS hours.
- **Read:** Ho et al., [Denoising Diffusion Probabilistic Models](https://arxiv.org/abs/2006.11239) (2020); Song et al., [Denoising Diffusion Implicit Models](https://arxiv.org/abs/2010.02502) (2021). The proposed objective ablation is specific to this repository.

**E12. Guide a pretrained denoiser with the standalone perceptual loss.**

- **Hypothesis:** a frozen pretrained diffusion prior can turn perceptual guidance into useful stylization more efficiently than learning image synthesis from the small flower set.
- **Smallest answer:** after E11's diagnostics, choose one fixed pretrained image-to-image latent diffusion checkpoint; use six content images, two styles, and two seeds. Compare unguided image-to-image against two guidance strengths at the same starting noise level, 30–50 sampling steps, and fixed prompts. Score decoded predicted-clean images at late/low-noise steps; compare against a feed-forward model too. Change the starting noise level only in a subsequent comparison.
- **Needed:** an optional sampler that enables gradients through denoising/decoding into the current latent while freezing model parameters, an explicit gradient-step rule and norm cap, model/VAE identifiers, and logged schedules. A loss on latent tensors is not the RGB VGG loss. The existing `sample` is wholly under `no_grad`, so this is a separate experimental sampling path (`diffuser/inference.py:27`), not a switch already available.
- **Cost:** zero model training; budget 2–6 rented-GPU inference hours and 1–2 engineering days. Apple Silicon feasibility/time depends strongly on memory and the chosen checkpoint; do not promise it from the tiny-U-Net timings.
- **Support / stop:** continue only if guidance reliably improves reference-style preference over unguided samples while meeting the content constraint, and its latency buys a result the fast baseline cannot provide. Stop if it optimizes VGG texture artifacts, changes object identity, or only matches what the existing feed-forward model already does.
- **Read:** Meng et al., [SDEdit: Guided Image Synthesis and Editing with Stochastic Differential Equations](https://arxiv.org/abs/2108.01073) (2022); Rombach et al., [High-Resolution Image Synthesis with Latent Diffusion Models](https://arxiv.org/abs/2112.10752) (2022). These motivate pretrained priors/image editing; the particular VGG-guidance procedure above is a proposal, not a claimed reproduction.

**Ideas to skip or defer**

- **A bigger diffusion model trained from scratch now:** size cannot settle the content-target conflict, and the evidence above contains no successful validation baseline. Prefer E11, then a pretrained-prior experiment if warranted.
- **A full AdaIN/style-embedding training platform now:** start with three-style conditional normalization and an external pretrained AdaIN reference (E8). A learned encoder for unseen styles adds a decoder/training-data problem; it should replace a demonstrated limitation rather than become scaffolding for hypothetical styles.
- **CLIP/DINO/transformer everything:** first compare a cheap spatial backbone and calibrated VGG controls. Semantic similarity alone is not the same research question as brushwork/color statistics. A semantic-loss branch becomes worthwhile if E1 reveals specific content-identity failures; no present result establishes that need.
- **Huge Gram alternatives or transport sweeps:** E4 should first establish whether even mean/std versus full Gram matters. Many distribution losses at once make scale calibration dominate the experiment.
- **FID as the primary score on a few paintings:** matching a small reference-image distribution can reward discarding content; it does not answer this project's paired content/style question. Keep any later distribution metric supplementary to E1's content constraint and controls.
- **INT8, browser WebGPU, or tiled 4K as defaults before measurements:** E10 first needs parity and an actual speed benefit. Tiling is particularly nontrivial because instance normalization depends on each input's spatial statistics, so tile-local statistics differ from whole-image statistics (inference from `style_transfer/models.py:47`, `style_transfer/architectures/residual_block.py:10`). Overlap alone is not a demonstrated equivalence guarantee.
